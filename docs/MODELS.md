# Выбор модели

## Рекомендация

**Семейство Qwen3.** Основная модель — `qwen3:14b`, при слабом GPU — `qwen3:8b`.

Режим рассуждений отключается (`LLM_EXTRA_BODY='{"reasoning_effort":"none"}'` для Ollama,
`chat_template_kwargs.enable_thinking=false` для vLLM). На тесте он дал +1 п. п. качества ценой
замедления в 2,5–3,5 раза (см. ниже) — для интерактивной работы это невыгодно.

Сервер модели нужно запускать с контекстом не меньше 16K (`OLLAMA_CONTEXT_LENGTH=16384`):
по умолчанию Ollama берёт 4K, и длинный документ вместе с ответом в него не помещается.

| Сервер | Модель | Видеопамять, контекст 4K / 16K |
|---|---|---|
| Демо-стенд, GPU 12–16 ГБ | `qwen3:14b` | 9,0 / 11 ГБ |
| GPU 8 ГБ | `qwen3:8b` | 5,2 / 7,5 ГБ |
| Сервер 24–48 ГБ, эксплуатация | Qwen3-32B или Qwen3-30B-A3B (vLLM) — **не тестировались** | — |

Видеопамять при 4K записана скриптом сравнения (`/api/ps` Ollama), при 16K — замерена командой
`ollama ps` после запроса с `num_ctx=16384`.

Запасной вариант — `gemma3:12b`: проверка и письма без ошибок, но во всех прогонах ошибается
в арифметике и форматах адресов при переносе таблиц.

## Как тестировали

`make bench` (скрипт `backend/scripts/bench.py`) прогоняет модель через те же промпты, что и
приложение, на всех 9 образцах (3 документа на проверку, 3 обращения, 3 таблицы), по 3 прогона,
и проверяет результат автоматически:

- **Проверка по нормативке** — исчезли ли ссылки на отменённые акты, появились ли правильные
  замены, применены ли нормы (срок регистрации 3 дня, 30 дней, уведомление РКН за 24 часа и т. п.),
  не переписан ли документ сверх нужного (сходство с исходником ≥ 0,6).
- **Письмо** — учтены ли все факты из позиции исполнителя и вопросы заявителя, есть ли обращение
  и подписант, нет ли Markdown, ссылок на недействующие акты и **выдуманных телефонов/номеров**.
- **Таблицы** — сравнение каждой ячейки с эталоном.

Стенд: RTX 5070 Ti 16 ГБ, Ollama 0.31.2, модели в квантовании Q4_K_M, temperature 0.2, контекст
Ollama по умолчанию (4K — образцам его хватает). Время — среднее на один документ без учёта
первой загрузки модели.

Все модели прогонялись одной версией кода (коммит `a543998`) за один запуск. Исходные отчёты:
[`bench/main-summary.md`](bench/main-summary.md) и [`bench/main-results.json`](bench/main-results.json)
(все замечания по каждому прогону).

### Характерные ошибки (из 3 прогонов)

- **qwen3:14b** — 3 из 3 относит «Во дворе не вывозят мусор…, примите меры» к заявлению, а не к
  жалобе (спорный случай); по одному разу — арифметический сбой, пропуск срока 30 дней, пропуск
  вопроса о водоотводе.
- **qwen3:8b** — 3 из 3 пропускает вопрос о водоотводе в письме, не приводит год «15.03.26» к
  четырём цифрам, пишет «квартира 15» вместо «кв. 15».
- **gemma3:12b** — 3 из 3 ошибается в расчёте 52 000 × 1,15 и в форматах улиц и помещений.
- **T-lite-it-2.1** — лучшая на таблицах и самая быстрая из качественных, но в 4 из 6 писем
  **выдумывает телефон**, а в ТЗ 3 из 3 оставляет ссылку на отменённый 94-ФЗ. Для официальной
  переписки это неприемлемо без дополнительного контроля.
- **qwen3.5:9b** — 3 из 3 пропускает замены на 149-ФЗ и ГОСТ Р 7.0.8-2013, не определяет регион
  по городу.
- **YandexGPT-5-Lite-8B** — хорошие письма, но при актуализации регламента 3 из 3 оставляет ссылки
  на отменённые акты; на штатной выгрузке 3 из 3 не возвращает JSON, в остальных таблицах не
  соблюдает форматы телефонов и номеров домов.
- **qwen3:1.7b** — годится только для простых писем.

### Ограничения теста

9 образцов — демонстрационная выборка, а не статистически значимый тест: разница в 1–2 п. п.
между первыми тремя моделями в пределах шума. Перед внедрением стоит собрать 50–100 реальных
обезличенных документов заказчика и прогнать `make bench` на них. Лицензии моделей (Qwen3 —
Apache 2.0, у Gemma, YandexGPT и T-lite — собственные условия) нужно проверить с юристами под
конкретный сценарий использования.

## Как повторить

```bash
ollama pull qwen3:14b qwen3:8b gemma3:12b
REPEATS=3 make bench MODELS="qwen3:14b qwen3:8b gemma3:12b"
# отчёт: backend/bench-results/<дата>/summary.md (в шапке — коммит и параметры запуска)

# с рассуждениями (make подставляет LLM_EXTRA_BODY из .env, поэтому напрямую):
cd backend && LLM_BASE_URL=http://localhost:11434/v1 LLM_EXTRA_BODY='{}' SECRET_KEY=bench-bench-bench-bench-bench-bench \
  uv run python scripts/bench.py qwen3:14b

# видеопамять при контексте 16K:
curl -s localhost:11434/api/generate -d '{"model":"qwen3:14b","prompt":"hi","stream":false,"options":{"num_ctx":16384,"num_predict":1}}' >/dev/null && ollama ps
```
