# Актуализация справочника нормативных актов

Проверка документа и ответы на обращения опираются на один файл —
`backend/app/data/norms.json`. Модель не знает статусов законов сама: она получает только то,
что найдено в справочнике. Поэтому актуальность проверки = актуальность этого файла.

## Как справочник используется

- **Проверка документа** (`services/normcheck.py`). Ссылки в тексте ищутся регулярными
  выражениями из `patterns`. По найденным актам собирается справка (статус, дата утраты силы,
  замена, ключевые нормы), и модель переписывает текст только по ней.
- **Ответ на обращение** (`services/letters.py`). В промпт попадают действующие акты, упомянутые
  в обращении, и всегда — `fz-59`, `fz-8-2009`, `fz-125` (`ALWAYS_CITED_NORMS`) вместе с их `facts`.
- Ссылки вида `NNN-ФЗ`, `ГОСТ …`, `СанПиН …`, `СП …`, которых нет в справочнике, показываются
  как «нет в базе, проверьте вручную». Приказы, постановления и указы без записи в справочнике
  не распознаются вовсе.

## Формат записи

```json
{
  "id": "fz-24-1995",
  "title": "Федеральный закон от 20.02.1995 № 24-ФЗ «Об информации, информатизации и защите информации»",
  "status": "repealed",
  "since": "2006",
  "replaced_by": "Федеральный закон от 27.07.2006 № 149-ФЗ «Об информации, информационных технологиях и о защите информации»",
  "comment": "Необязательное пояснение для пользователя и модели.",
  "patterns": ["(?<![\\d-])24-ФЗ", "Об информации, информатизации и защите информации"],
  "facts": ["Конкретная норма со ссылкой на статью (ч. 1 ст. 12)."]
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | Уникальный ключ латиницей (`fz-152`, `gost-6.30-2003`). Используется в тестах и в `ALWAYS_CITED_NORMS` |
| `title` | да | Полное официальное наименование: вид, дата, номер, название |
| `status` | да | `active` — действует; `repealed` — утратил силу; `partially` — применяется ограниченно |
| `since` | для `repealed`/`partially` | С какой даты (`01.07.2018` или год) |
| `replaced_by` | для `repealed`/`partially` | Чем заменён. Строка **дословно** равна `title` записи о новом акте |
| `comment` | нет | Особенности перехода: смена терминов, что именно осталось в силе |
| `patterns` | да | Регулярные выражения (Python `re`, без учёта регистра), по которым акт находится в тексте |
| `facts` | нет | Ключевые нормы — сроки, порядок. Модель приводит документ в соответствие с ними |
| `garant_topic` | нет | Номер документа в ГАРАНТ (число из ссылки `…/#/document/12345`), если сверка нашла не тот документ |

**Наследование норм.** У отменённого акта `facts` обычно нет: проверка берёт их у акта из
`replaced_by`. Это работает, только если `replaced_by` совпадает с `title` новой записи
символ в символ (включая кавычки «» и знак №). Не совпало — модель заменит ссылку, но не
исправит сроки.

## Типовые изменения

### Акт утратил силу

1. Добавьте запись о новом акте со `status: "active"`, `patterns` и `facts`, если в нём есть
   нормы, которые обычно встречаются в документах (сроки, обязательные процедуры).
2. В записи старого акта поставьте `status: "repealed"`, `since`, `replaced_by` = `title` новой
   записи. Его `facts` удалите — теперь они берутся у нового акта.
3. Если вместе с актом сменилась терминология (ЭЦП → электронная подпись), добавьте в `patterns`
   старый термин и опишите замену в `comment` — см. запись `fz-1-2002`.

### Акт заменён частично

`status: "partially"`, `since`, в `replaced_by` — акт, на который теперь нужно ссылаться, в
`comment` — где старый акт ещё применяется. Образец — `fz-294`.

### В действующий акт внесены изменения

Поменяйте `facts` (сроки, номера статей). `title` не трогайте: редакцию в наименовании не
указывают. Записи, которые ссылаются на этот акт через `replaced_by`, подхватят новые нормы
автоматически.

### Новый акт, который нужно распознавать

Добавьте запись со `status: "active"`. Даже без `facts` это полезно: ссылка перестанет
помечаться как «нет в базе», а в ответах на обращения акт будет назван точным наименованием.

## Как писать `patterns`

- Номер федерального закона — с ограничителем слева: `(?<![\\d-])59-ФЗ`. Без него `59-ФЗ`
  совпадёт внутри `159-ФЗ`, а `24-ФЗ` — внутри `124-ФЗ`.
- Добавьте точное название акта без даты: в документах часто пишут «Федеральный закон
  "Об электронной подписи"» без номера.
- Пробелы — `\\s*` или `\\s+`, точки — `\\.`: `ГОСТ\\s*Р\\s*6\\.30-2003`. В JSON обратная косая
  черта удваивается.
- Падежи — через `\\w+`: `электронн\\w+ цифров\\w+ подпис`.
- Не делайте шаблон слишком общим: `ЭЦП` уместен (термин однозначно устарел), а «закон о
  закупках» — нет.

## Проверка после правки

```bash
# 1. Акт находится в тексте и получает нужные нормы
cd backend && uv run python -c "
from app.services.normcheck import find_references
for f in find_references('согласно Федеральному закону № 24-ФЗ и ГОСТ Р 6.30-2003'):
    print(f['norm_id'], f['status'], f['replaced_by'], f['facts'])
"

# 2. Тесты: образцы по-прежнему находят свои акты, номера не путаются
make check
```

Если правка меняет поведение на образцах (например, акт из образца снова действует), обновите
ожидания в `backend/tests/test_app.py` (`test_find_references_on_examples`), правила
`CHECK_GOLD` в `backend/scripts/bench.py` и при необходимости эталонные редакции
`backend/app/data/examples/docs/check/*.expected.docx` (затем `make examples`).

Наконец, откройте «Проверку документа», вставьте фрагмент со ссылкой на изменённый акт и
убедитесь, что замечание и правка корректны.

## Выкладка

Справочник читается один раз при старте бэкенда и входит в образ. После правки:

- **через CI** — коммит в `main`, CI собирает новый образ, на сервере `make up-prod`;
- **без пересборки** — смонтировать файл поверх встроенного, добавив сервису `backend`
  в `docker/docker-compose.yml`:

  ```yaml
  volumes:
    - ./norms.json:/app/app/data/norms.json:ro
  ```

  и перезапустить бэкенд:
  `docker compose --env-file .env -f docker/docker-compose.yml restart backend`.
  Путь `./norms.json` считается от каталога `docker/`.

## Отслеживание изменений по pravo.gov.ru (без токена)

Официальный портал опубликования [publication.pravo.gov.ru](http://publication.pravo.gov.ru)
отдаёт данные через открытый API без токена
([описание](http://publication.pravo.gov.ru/help)). Он не говорит «акт отменён», но показывает
новые публикации, а этого достаточно, чтобы заметить изменение. Отслеживание выполняет
`backend/scripts/pravo_sync.py`:

```bash
make pravo                     # публикации за последние 30 дней
make pravo SINCE=2026-08-01    # с указанной даты
```

Как работает: у API нет фильтра по дате, поэтому документы листаются от новых к старым
(`GET /api/Documents`, блоки `president`, `government`, `federal_authorities`) до даты `SINCE`.
Название каждого документа сверяется с теми же `patterns`, что и в проверке документов. Если
опубликован акт «О внесении изменений в Федеральный закон … "О порядке рассмотрения обращений
граждан…"» — отслеживаемый `fz-59` попадёт в отчёт. Отбираются только документы со словами об
изменении/отмене («внесении», «утратившим силу», «признании»), чтобы не реагировать на первичные
публикации.

Пример вывода (реальный прогон):

```
Отслеживается актов: 19; публикаций с 2026-08-01 по отслеживаемым актам: 3
- fz-44: 2026-08-04 — Федеральный закон от 04.08.2026 № 279-ФЗ "О внесении изменений в
  Федеральный закон "О контрактной системе в сфере закупок…"
  http://publication.pravo.gov.ru/document/0001202608040004
```

Как и сверка с ГАРАНТ, скрипт справочник **не меняет** — он даёт юристу список публикаций для
проверки по разделу «Типовые изменения». Код выхода 1 при находках удобен для запуска по
расписанию (cron, CI).

**Ограничения.** Номера федеральных законов повторяются каждый год, поэтому шаблон по номеру
(`294-ФЗ`) поймает и новый, не связанный закон с тем же номером — публикацию проверяет человек.
Инструмент видит только документы, опубликованные на портале (федеральные акты и акты субъектов
с 2011 года); историю отмен до этого и статусы ГОСТов по нему не получить — для статусов нужен
ГАРАНТ или СПС.

## Автоматическая сверка с ГАРАНТ

У системы ГАРАНТ есть API «Гарант Коннект»
([документация](https://www.garant.ru/mobileonline/api/documentation/)); у КонсультантПлюс
открытого API нет, интеграция с ним обсуждается с региональным представителем. Сверку выполняет
`backend/scripts/garant_sync.py`:

```bash
# в .env: GARANT_TOKEN=… (выдаёт обслуживающая организация ГАРАНТ)
make garant                    # изменения за последние 30 дней
make garant SINCE=2026-09-01   # с указанной даты
```

Для каждой записи справочника скрипт:

1. находит документ в ГАРАНТ поиском по `title` (`POST /v2/search`) и сверяет номер акта в
   наименовании; при ошибке номер документа задаётся вручную полем `garant_topic`;
2. запрашивает статус (`GET /v2/topic/{topic}`: «Действующие» / «Утратившие силу» /
   «Не вступившие в силу») и сравнивает его со `status`. `partially` считается действующим;
3. одним запросом на 100 актов проверяет, менялись ли они с даты `SINCE`
   (`POST /v2/find-modified`): утратил силу, изменён, вступила в силу новая редакция и т. п.

Пример вывода:

```
Сверено актов: 19, замечаний: 2
- fz-152: изменения с 2026-09-01 — 2026-09-15 вступила в силу новая редакция; сверьте facts и статус
- fz-44: в справочнике «active», в ГАРАНТ «Утратившие силу» — … (topic 70353464)
```

Справочник скрипт **не меняет**: ГАРАНТ сообщает, что акт утратил силу или изменён, но не
говорит, чем он заменён и какие сроки поменялись. Это вносит юрист по разделу «Типовые
изменения». Код выхода 1 при замечаниях позволяет запускать сверку по расписанию (cron, CI) и
отправлять отчёт ответственному.

Лимиты Интернет-версии: «Информация о документе» — 300 вызовов в месяц (по одному на акт за
запуск, то есть ~15 полных сверок справочника из 19 актов), «Документы на контроле» и
простановка ссылок — 1000 в месяц суммарно, не больше 20 запросов в секунду. В Интранет-версии
(«Проксима», адрес сервера + `/api` в `GARANT_API_URL`) доступны только поиск, экспорт и
информация о документе, причём последние два — только для клиентских документов из БВД;
для сверки федеральных актов она не подходит.

## Откуда брать сведения

Статусы и тексты актов сверяйте по официальным источникам: [pravo.gov.ru](http://pravo.gov.ru)
(официальное опубликование), справочно-правовые системы «КонсультантПлюс» и «Гарант», для
стандартов — [Росстандарт](https://www.rst.gov.ru). Демо-справочник на 19 актов составлен
вручную; в эксплуатации его стоит регулярно сверять с СПС (например, раз в месяц) или
генерировать из выгрузки СПС в том же формате.
