# Бесплатные источники актуальных нормативных актов и план интеграции

Дата анализа: 16.11.2026. Все пункты с пометкой «проверено» — это живые запросы с рабочей
машины в этот день, без токенов и регистрации.

## Вывод

Статус и действующую редакцию федеральных актов можно получать бесплатно из двух разделов
официального портала pravo.gov.ru, и вместе они закрывают то, для чего сейчас нужен платный
ГАРАНТ:

| Что нужно справочнику | Источник | Сейчас |
|---|---|---|
| «Вышло что-то новое по акту» | API опубликования `publication.pravo.gov.ru` | есть, но листает неэффективно |
| Статус: действует / утратил силу | ИПС «Законодательство России» `pravo.gov.ru/proxy/ips/` | нет (только через ГАРАНТ) |
| «У акта появилась новая редакция» | ИПС, список редакций в карточке | нет |
| Текст действующей редакции | ИПС, `doc_itself` | нет |
| Статус ГОСТ | каталог `gostinfo.ru` (Институт стандартизации) | нет |
| Статус СанПиН и СП | ИПС, по утвердившему постановлению | нет |

Автоматической сверкой статуса закрываются 70 записей из 71 (кроме уже отменённого СанПиН

ответ на вопрос «чем акт заменён» и содержание `facts` — это по-прежнему вносит юрист.

**Сверка уже нашла устаревшие записи** (по карточкам gostinfo.ru на 16.11.2026):

## Источники

### 1. API официального опубликования — использовать, доработать

`http://publication.pravo.gov.ru/api/Documents`, документация — `/help`. Уже подключён
(`backend/app/services/sources.py`).

Проверено:

- Фильтр по дате **есть**: `PublishDateFrom=01.11.2026` (формат `ДД.ММ.ГГГГ`; ISO-дата молча
  игнорируется — видимо, поэтому в коде записано, что фильтра нет). `PageSize` допускает 200.
- Объём: федеральные блоки с 01.11 по 16.11 — 55 + 199 + 144 документов, то есть 3–4 запроса
  вместо листания до 400 страниц на блок.
- `Number` + `NumberSearchType=0` ищет точный номер (`59-ФЗ` → 15 документов за разные годы).
- `Name` работает, но строг к формулировке (без блока по названию 59-ФЗ вернул 0) — надёжнее
  фильтровать по дате и сверять названия своими `patterns`, как сейчас.
- `DocumentText` (поиск по тексту) в проверке вернул 0 — не полагаться.
- `/api/Document?eoNumber=…` — карточка; `/file/pdf?eoNumber=…` — PDF (образ опубликования,
  не редакция с изменениями).
- HTTPS на этом хосте не отвечает — остаётся HTTP.

Ограничение прежнее: это лента публикаций, статуса акта в ней нет.

### 2. ИПС «Законодательство России» — подключить, главный источник статуса

`http://pravo.gov.ru/proxy/ips/` — официальная система с актуальными редакциями.
Документированного API нет, но страницы отдаются обычным GET; `robots.txt` портала ничего не
запрещает. Кодировка ответов и параметров — windows-1251.

Проверено:

- **Поиск по номеру и дате** →
  `?list_itself=&bpas=cd00000&a8=<номер>&a8type=1&a7type=1&a7date=20.02.1995&sort=7&page=first`
  — для «24-ФЗ от 20.02.1995» вернул ровно 1 документ. Без даты — 33 (номера повторяются по
  годам), `lstsize=200` отдаёт все одной страницей.
- **Статус в списке**: «Действует без изменений», «Действует c изменениями», «Утратил силу».
  24-ФЗ 1995 года помечен «Утратил силу» — совпадает со справочником.
- **Карточка** `?docbody=&nd=<id>` — список редакций: для 59-ФЗ «10 - от 28.12.2024 № 547-ФЗ».
- **Текст действующей редакции** `?doc_itself=&nd=<id>&fulltext=1` — 67 КБ HTML, в шапке
  перечислены все изменяющие законы. В карточке есть и ссылка на выгрузку RTF
  (`?savertf=&nd=<id>&page=all`), сама выгрузка не проверялась.

Риски: формат HTML недокументирован и может поменяться; редакции появляются с задержкой после
опубликования; нагрузку держать вежливой (последовательно, раз в сутки).

### 3. Каталог стандартов gostinfo.ru — подключить для ГОСТ

`https://www.gostinfo.ru/catalog/gostlist/?searchString=<обозначение>` — каталог ФГБУ
«Институт стандартизации» (подведомственно Росстандарту). API нет, обычный GET, UTF-8;
`robots.txt` запретов не содержит.

Проверено на шести стандартах (четыре из справочника и два новых):

- Поиск по обозначению без префикса (`7.0.97-2016`) каждый раз вернул ровно 1 документ.
- В выдаче есть «Статус: Действует / Заменен» — одного запроса на стандарт достаточно.
- Карточка `/catalog/Details/?id=<guid>` даёт «Дата введения в действие» и «Дата огр. срока
  действия» — готовое значение для `since`.
- Чем стандарт заменён, карточка явно не называет. Преемник обычно находится поиском по тому
  же номеру без года (`7.0.97`), но это подсказка юристу, а не автозаполнение.

Открытые данные Росстандарта (`rst.gov.ru/opendata/7706406291-nationalstandards`, CSV
«Обозначение; Заглавие; Статус; Код ОКС», 14 968 строк) для сверки **не годятся**: последняя
выгрузка от 08.08.2024, в ней ГОСТ Р 7.0.97-2016 ещё «Действует», а отменённых стандартов нет
вовсе.

### 4. СанПиН и СП — через ИПС

В справочнике `sp-2.2.3670-20` — санитарные правила, а не строительный свод: как и СанПиН, они
утверждены постановлением Главного государственного санитарного врача и есть в ИПС.

Проверено: поиск по номеру и дате **постановления** находит ровно один документ со статусом —
№ 40 от 02.12.2020 (СП 2.2.3670-20) и № 2 от 28.01.2021 (СанПиН 1.2.3685-21), оба «Действует
без изменений». Старый СанПиН 2.2.2/2.4.1340-03 по № 118 от 03.06.2003 не нашёлся, поиск по
тексту обозначения тоже ничего не дал.

Следствие: в `title` этих записей реквизитов постановления нет, поэтому `ips_nd` для трёх
записей задаётся один раз вручную; отменённый СанПиН остаётся без сверки (его статус уже не
изменится).

## План интеграции

**Статус на 16.11.2026: этапы 1–5 реализованы**, с одним изменением принципа по решению
владельца: сверка статусов не только сообщает, а **сразу вносит** расхождения в справочник
(в БД) с пометкой «не проверено» и пояснением `sync_note`; юрист потом подтверждает или
исправляет запись в админке. Реализация — `backend/app/services/status_sync.py`, описание —
`docs/NORMS.md`, раздел «Автоматическая сверка статусов». Отличия от плана ниже: у кодексов
редакция не отслеживается (ИПС отдаёт их карточку минутами), законы РФ 1990–1993 ищутся с
римской «I» в номере.

Прочие отступления от плана (сознательные):

- **`replaced_by` заполняется автоматически** — вопреки пункту «Сознательно не делаем», в духе
  решения «сначала автоматически». Источник — действующий ГОСТ того же номера и перенос через
  отменённую замену из справочника. Если новой замены нет в справочнике (ГОСТ Р 7.0.8-2025),
  сверка добавляет о ней запись без `facts` с пометкой «не проверено» — нормы заполняет юрист.
- **Параллельно 4 запроса** вместо последовательных: иначе кнопка ждёт 5+ минут.
- **Реквизиты СанПиН и СП — полем `ips_ref`**, а не вручную найденным `ips_nd`: `ips_nd`
  сверка находит и сохраняет сама, но пока ищет акт каждый раз заново.
- **Отдельная кнопка и отчёт** «Сверить статусы» рядом с лентой публикаций: сверка меняет
  справочник, лента — только сообщает, смешивать их в одном отчёте нельзя.
- CLI — `python -m app.services.status_sync`, а не `scripts/`: каталог не входит в образ.
- Не сделано: находка «замена отсутствует в справочнике» (висячий `replaced_by`).

### Этап 1. Фильтр по дате в существующей сверке (≈1 час)

`sources.fetch_pravo_changes`: добавить `PublishDateFrom=since.strftime("%d.%m.%Y")`,
`PageSize=200`, снизить `MAX_PAGES`; остановку по дате оставить как страховку. После этого
кнопка «Проверить обновления» в админке может обходить все три блока, как CLI.

Проверка: существующие тесты `test_pravo.py` + сравнить вывод `make pravo SINCE=2026-08-01` до
и после — список находок должен совпасть.

### Этап 2. Статус из ИПС (≈полдня)

1. `sources.py`: `fetch_ips_status(client, norm) -> {nd, status} | None`.
   Номер и дата берутся из `title` (`от ДД.ММ.ГГГГ № N`); запрос из п. 2; при 0 или >1
   результатах — `None` с пометкой «не найден однозначно». Найденный `nd` сохраняется в записи
   полем `ips_nd` (по образцу `garant_topic`), чтобы дальше ходить напрямую.
2. Сопоставление: «Утратил силу» ↔ `repealed`; «Действует…» ↔ `active` и `partially`.
3. Вывод расхождений — в тот же отчёт: CLI `make pravo` и ответ `/api/admin/norms/updates`
   (новый тип находки рядом с публикациями). Отдельная цель и отдельный экран не нужны.
4. СанПиН и СП сверяются по заданному вручную `ips_nd` (см. п. 4 источников). Записи без
   `ips_nd` и без номера с датой в `title` пропускаются с явным счётчиком «не сверено».

Проверка: тест на `httpx.MockTransport` с сохранённым фрагментом списка ИПС (cp1251) — разбор
статуса и случай «несколько результатов»; живой прогон по всему справочнику и сверка с
11 записями `repealed`.

### Этап 3. Отслеживание редакций (≈2–3 часа)

Из карточки `?docbody=&nd=` брать последнюю строку списка редакций и хранить в записи
(`ips_revision`). Изменилась — находка «новая редакция, сверьте `facts`» и `verified: false`.
Это точнее сверки названий публикаций: нет ложных срабатываний на совпавший номер другого года.

В админке рядом с записью — ссылка на текст действующей редакции в ИПС.

### Этап 4. Статус ГОСТ из gostinfo.ru (≈2–3 часа)

1. `sources.py`: `fetch_gost_status(client, norm) -> {status, since} | None` для записей с
   `id`, начинающимся на `gost-`. Обозначение берётся из `title` (всё после «ГОСТ Р » до «»);
   запрос поиска, при ровно одном результате — статус из выдачи и дата ограничения срока из
   карточки. Иначе `None` и счётчик «не сверено».
2. Сопоставление: «Заменен», «Отменен» ↔ `repealed`; «Действует» ↔ `active`. Сверяется и
   `since`.
3. **Проверка `replaced_by`**: если запись ссылается на акт, которого нет в справочнике или
   который сам не `active`, — отдельная находка «замена устарела». Это ловит случай
   ГОСТ Р 6.30-2003 → 7.0.97-2016 → 7.0.97-2025 и работает для всех записей, без сети.
4. Находки — в тот же отчёт, что и этапы 2–3.

Проверка: тест на `httpx.MockTransport` с сохранённым фрагментом выдачи; живой прогон должен
показать три расхождения из таблицы в начале документа.

### Этап 5. Документация

`docs/NORMS.md`: раздел про ИПС, исправить утверждение об отсутствии фильтра по дате, ГАРАНТ
перевести в «необязательный, если есть договор». `CLAUDE.md` — одна строка про второй источник.

### Сознательно не делаем

- **Подмешивание текста акта в промпт** (поиск по тексту редакции). Проверка построена на
  коротких `facts`, а контекст локальной модели — 16K. Вернуться, если юристу не будет хватать
  `facts`.
- **Планировщик внутри приложения.** Код выхода 1 у `make pravo` уже позволяет запускать по cron
  или в CI.
- **Автоматическое заполнение `replaced_by` и `facts`.** Источники этого в машинном виде не
  дают; ошибка здесь хуже отсутствия записи.
- **Строительные своды правил, законопроекты, региональные акты** — в справочнике их нет; см.
  таблицу «Остальное».
- **Общий интерфейс «источник статуса».** Три функции в `sources.py` с выбором по `id` записи;
  абстракция понадобится, если источников станет больше.

## Открытые вопросы

0. Кто и когда правит три устаревшие записи ГОСТ: это меняет образцы и эталоны бенча.

1. Откуда будет работать прод: pravo.gov.ru проверен только с рабочей машины и только по
   HTTP — проверить доступность с целевого сервера до этапа 2.
2. Нужна ли сверка статуса по кнопке (71 последовательный запрос) или достаточно ночного
   запуска с сохранением результата.
3. Есть ли в `title` всех кодексов и СанПиН дата и номер — если нет, для них задать `ips_nd`
   вручную. Находит ли ИПС постановления и указы тем же запросом — проверен только ФЗ.
